## 实施原则

* 注册、中文/英语文本、原创可运行资源、服务端权威、客户端隔离、业务探针和本文档同批交付。
* 信件、死亡笔记和八音盒的提交均使用服务端会话，重新核验玩家、手持实例、槽位、修订、长度、距离、权限和目标；不执行拼接命令。
* 任意门不强加载区块；安全落点是独立 `Block` 与 `BlockItem`，只在关联、区块、维度和碰撞均通过时传送。
* 在线音频仅允许安全 HTTPS URL；服务端不下载或转发，播放事件仅发送给开始时当前在线的全服玩家。MP3 必须是许可证兼容的纯客户端解码实现，专服绝不能加载音频客户端类。
* ciTest 仅存在于 `src/ciTest` 与独立 Jar，不能预写 marker、跳过失败、删除场景或放宽生产校验。

## 当前批次

第一批已写入信件与死亡笔记的生产链路，尚未取得动态结论：

* 信件普通右键只发送受过滤的只读 S2C 正文；潜行右键创建含容器、会话、手持槽位、实例 UUID 和修订号的服务端菜单。提交只接受统一换行的纯文本，拒绝控制字符与 `§`，并按服务器配置检查最多 512 Unicode 码点、16 行；成功后才递增 NBT 修订。
* 死亡笔记菜单以相同的实例与修订边界校验提交时在线的玩家名，并立即固化目标 UUID 与到期游戏刻到主世界 `DeathNoteSavedData`；到期仅按 UUID 查仍在线的目标，以绕过无敌的原版伤害结算，绝不拼接或执行命令。
* 本批新增原创 16×16 像素图标、物品模型、中文/英文文本和客户端隔离 Screen；质量工作流同步断言三种新网络包方向及 C2S 手持实例复验。
* ciTest 新增真实双客户端路径：Alice 以生产 `KeyMapping` 右键、潜行右键和 Screen 控件进入读信、编辑和死亡笔记；Bob 仅在真实死亡界面出现后写 marker。负例覆盖换手、伪造容器/实例/修订、一次性会话重放、控制字符、码点/行数超限和离线目标；生命周期工作流另保存并核对尚未到期的死亡笔记 UUID/到期刻。
