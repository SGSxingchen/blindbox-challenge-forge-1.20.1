## 实施原则

* 注册、中文/英语文本、原创可运行资源、服务端权威、客户端隔离、业务探针和本文档同批交付。
* 信件、死亡笔记和八音盒的提交均使用服务端会话，重新核验玩家、手持实例、槽位、修订、长度、距离、权限和目标；不执行拼接命令。
* 任意门不强加载区块；安全落点是独立 `Block` 与 `BlockItem`，只在关联、区块、维度和碰撞均通过时传送。
* 在线音频仅允许安全 HTTPS URL；服务端不下载或转发，播放事件仅发送给开始时当前在线的全服玩家。MP3 必须是许可证兼容的纯客户端解码实现，专服绝不能加载音频客户端类。
* ciTest 仅存在于 `src/ciTest` 与独立 Jar，不能预写 marker、跳过失败、删除场景或放宽生产校验；其类只能声明在独立的 `cn.blindboxchallenge.citest` 包树中，可引用生产公开类型但绝不能与正式模组共享 Java 包，否则 Forge 模块层会拒绝启动。八音盒生产声源只额外公开事件 UUID、格式、缓存命中和声源位置等只读元数据，供独立探针包装生产 `SoundInstance` 后观察真实 PCM；探针不获得下载、解码或播放控制入口。

第四批已开始写入 047-B 木质手工八音盒的最小完整链路，尚未取得动态结论：方块实体只持久保存实例 UUID、已规范化的 HTTPS URL 和修订号，不保存正在播放的事件，因此重登绝不补播。潜行右键或空配置右键打开服务端受控菜单；C2S 提交重新核验菜单、方块位置、距离、实例和修订，拒绝非 HTTPS、认证信息、片段、IP 字面量、localhost 与非 443 端口。普通右键只向**触发时已在线的玩家**发送一次 UUID 事件；服务端从不下载、缓存、解码或转发音频字节。客户端对每个重定向重新规范化 URL、DNS 解析并拒绝私网/保留地址；已通过校验的公网 IP 被固定到实际 TLS 连接，同时保留 SNI 与 HTTPS 主机名校验，避免“预解析后又按域名连接”的 DNS 重绑定漏洞。下载禁用自动重定向、代理、压缩传输、Cookie/认证请求头，限制 3 跳、10 秒、16 MiB，验证 Content-Type 与 OGG/MP3 文件头；成功后按 URL 与内容 SHA-256 原子落盘并以 64 MiB LRU 清理。OGG 使用原版 `OggAudioStream`，MP3 使用仅客户端 JLayer 1.0.1（LGPL-2.1、独立 Jar-in-Jar、不重定位；完整许可证与 NOTICE 已随源树保存）解码 16-bit PCM，再经 Forge 的 `SoundInstance#getStream` 公开扩展点交给原版 SoundEngine。不得把这批静态实现写为安全或播放验收通过；真实 HTTPS、OGG/MP3、缓存、失败和新登录不补播探针仍须在 Hosted Runner 完成。

第四批静态加固追加：客户端把 IPv4-mapped、IPv4-compatible、标准 NAT64 嵌入 IPv4 与 IPv6 文档/保留前缀统一按真实目标拒绝；服务端对数字/点主机名直接拒绝而不做 DNS。每一跳 DNS、TCP、TLS、重定向和响应体共享一个 10 秒截止点，且客户端直接向已验证 IP 的 TLS socket 写固定 GET（无 URLConnection 回退、Cookie、认证或代理）；TLS socket 到期会主动关闭。缓存只信任普通非链接文件，并复算大小、魔数和 SHA-256；同 URL 合并单次下载、过期 `.part` 清理，避免并发覆盖与残留。OGG/MP3 都在客户端工作线程完整解码为有 128 MiB 上限的 PCM 后才交给原版音频线程，因此解码失败仍会回到客户端失败提示；同时至多两条远程音频占用解码/播放槽位，断线/换服通过连接代次忽略旧下载。JLayer 的 LGPL 与 NOTICE 已配置进入正式 Jar，并由质量门禁检查。任意门配对/传送和八音盒编辑/播放都同时重验 `Player.mayBuild()` 与 `Level.mayInteract` 的位置权限；任意门还要求双方各**恰好一个**安全落点，新增第二安全点即拒绝并清理双向关系。质量门禁拒绝不存在的带位置 `mayBuild` 调用，防止该 Forge 1.20.1 API 错误回归。为后续真实在线验收新增自制 0.25 秒正弦波 OGG/MP3 和截断失败夹具，只放 `src/ciTest/resources/ci-audio/`，有生成脚本、摘要与来源说明，正式 Jar 门禁明确排除它们。上述均仍是静态实现，不能替代 Hosted Runner 的真实验收。

第四批真实验收探针已追加但尚未在 Hosted Runner 得出结论：Alice 必须站在服务端布置的方块上，通过真实右键打开生产 `MusicBoxScreen`，分别提交 OGG、MP3、截断 OGG 三次 URL；两客户端都只在生产 `PlaySoundEvent` 进入原版音频引擎且其真实 `AudioStream.read()` 返回非空 PCM 后写一次原子 marker。服务端逐字段交叉核验两端同一事件 UUID、URL、声源、观察者、格式和缓存命中。初次 OGG 后工作流仅将 `raw.githubusercontent.com` 解析为回环地址；第二次相同 URL 若未先命中 SHA 缓存即被生产公网策略拒绝，故不能伪造为缓存成功。恢复公网解析后再验证 MP3，截断 OGG 必须先收到真实 S2C 再得到客户端失败事件且不得产生 PCM marker；最后真实踢出 Bob、经 `ConnectScreen` 重连后先连续 80 tick、再额外 40 tick 宽限不得收到历史播放事件。这里验证的是 **120 tick 有限观察窗口**，不能虚报为无限期数学证明。临时阶段旗标只安排顺序，不是成功 marker；所有结果文件由客户端或服务端事实生成，不能预写。

生命周期强杀恢复门禁的失败路径同样必须可审计：即使任一前置服务端日志等待超时，脚本也只复制已产生的 `first.log`、`second.log` 与已有 canonical 导出，并把日志尾部打印到 Hosted Runner；它保持非零失败、不创建 `result.json`、不补写任何 marker。该可观测性改动不是动态通过结论，后续仍须依据保存的首个真实错误修复。
