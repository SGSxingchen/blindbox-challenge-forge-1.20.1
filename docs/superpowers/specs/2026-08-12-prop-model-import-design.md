# 道具人工模型导入设计

## 目标与边界

将项目方在 `道具.zip` 中提供的九组人工模型导入 Forge 1.20.1 正式资源，并增加 GeckoLib 作为运行时前置，以保留人工几何设计、复杂旋转和后续动画扩展能力。本次不新增或删除注册物品，不改变业务功能、碰撞逻辑与奖池结构。

项目方已明确这些模型为人工制作并应导入项目。因此模型几何属于正式输入；配套贴图按技术条件处理：可用贴图规范化后导入，7800×7800 应援棒广告图降采样仍不适合像素资产，保留人工棒体几何并为其制作发行尺寸贴图。

## 映射

|八音盒|`music_box`|保留 39 元素结构；原生 JSON 不兼容的旋转表达通过 GeckoLib 模型管线承载，不擅自修改外形|

|奶龙|`floor_art_panel`|作为“蒙娜奶龙画像”的薄画板模型导入|
|应援棒|`bml_cheer_stick`|保留两段棒体几何；建立开/关及墙面状态兼容模型，贴图转换为小尺寸正式资源|
|白色人偶|`abstract_white_figurine`|导入 12 元素人偶模型并闭合粒子纹理|

## 资源实现

输入 ZIP 保持外部只读，不复制进仓库。增加 Forge 1.20.1 GeckoLib 依赖、`mods.toml` 强制前置声明和对应 Geo 模型资源；普通静态模型仍使用原生 JSON，需要保留复杂旋转或穿戴渲染的模型进入 GeckoLib 管线。贴图转换结果进入现有确定性贴图生成链或新的专用模型贴图载荷。所有正式输出必须能由 `--check` 检测漂移，并更新 `ASSET_MANIFEST.md` 的哈希。

方块状态、战利品表、注册 ID 和 Java 业务代码保持不变。JSON 模型不会改变碰撞盒；超一格模型须在客户端检查遮挡、放置方向和选取体验。三角锥不引入独立实体类或实体渲染器，仅接入物品态与盔甲态所需的 GeckoLib 渲染器。

## 兼容和质量要求

- 所有资源路径使用 `blindboxchallenge` 命名空间与英文小写 ID。
- 原生静态模型仅使用 Minecraft Java 1.20.1 支持的结构；复杂旋转和骨骼模型使用 GeckoLib 支持的 Geo JSON，不再强行降级成人工拆方块。
- 不将 30 MB 应援棒原图放入发行包；正式贴图保持二次幂尺寸并接受像素视觉检查。
- 每个方块模型必须解析成功、纹理引用闭合、物品模型可追溯至对应方块模型。
- 生成器检查、质量契约、Gradle 构建、专用服务器资源加载和真实客户端视觉检查均须通过。

## 验收视角

逐项检查背包图标、第一/第三人称、掉落物、物品展示框、方块放置方向和紫黑缺材质；抱枕还检查投掷实体与乘坐视觉，应援棒检查开关/墙面状态，交通锥检查头戴外观。任何模型若在人眼首看时与目标物品不符，优先修正轮廓、尺度和摆放，不用高光掩盖结构问题。
