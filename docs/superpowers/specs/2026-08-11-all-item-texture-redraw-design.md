# 全部物品贴图原创重绘设计

## 目标

将 `assets/blindboxchallenge/textures/item` 中 59 张正式 PNG 统一重绘为清晰、可辨认的 Minecraft 16×16 物品图标，彻底移除“把商品广告或包装图直接缩小”的视觉方式，同时保持资源 ID、模型引用和物品功能不变。

## 当前事实与范围

- 正式物品贴图共 59 张，对应 57 个注册物品；001 与 002 各有两个状态贴图。
- 台账为 54 张贴图提供了参考编号，为 `blind_box`、`packing_tool`、`letter`、`potato_chips`、`black_truffle_ham_cracker` 5 张提供自由设计空间。
- 当前工作区没有 `source-package/` 或 `archive/`，因此不能声称逐张读取了原参考图。本轮把 `ITEM_CATALOG.md`、`ASSET_MATRIX.md` 和资源 ID 的文字语义作为可验证参考。
- 当前未提交的 001 伸缩刀两张 PNG、模型、代码和生成器修改属于用户已有成果。本轮先保留，不由批量流程覆盖；它们仍计入 59 张正式资源的最终一致性检查。
- 本轮只处理 `textures/item/*.png`，不处理 11 张方块贴图和 1 张盔甲贴图，不改物品功能、注册、模型 JSON 或语言名称。

## 视觉规则

### 统一规则

1. 每张图只画一个物品主体，透明背景，四周保留 1 至 2 像素安全边距。
2. 采用硬边像素画、左上光源、深色轮廓和有限色板；禁止摄影背景、桌面、人物手持、海报排版、投影、水印和可读文字。
3. 最终尺寸固定为 16×16 RGBA；透明像素与不透明像素必须同时存在，不保留半透明广告抠图毛边。
4. 每项使用独立提示词和独立生成调用，不用一张综合广告图裁出多个物品。
5. 图像生成结果只作为原创母稿。最终以最近邻缩小、像素清理和 16×16 可读性为准，不以高分辨率母稿的细节丰富度为准。

### 有参考编号的物品

- 只保留物品类别、必要结构、基本轮廓和功能相关部件。
- 食品与饮料优先画食物或饮品本体；只有类别离不开容器时才使用无字原创容器。
- 书、试卷、纸币、徽章、旗帜只保留外形和材质，内部使用不可读的抽象像素符号。
- 涉及人物、角色或第三方知识产权时，不复刻人物脸、角色形象、商标、包装、口号和原版构图。

### 无可访问参考的物品

- `blind_box`：带清楚盒盖缝隙的深蓝紫小盒，正面使用原创星形封签，不使用大型问号广告牌。
- `packing_tool`：与盲盒同系列的封装夹具，突出夹持与封口结构。
- `letter`：折叠信封与封口结构，无地址、邮票文字或正文。
- `potato_chips`：三片金黄色弧面薯片，与 030 的条状/块状薯制零食区分。
- `black_truffle_ham_cracker`：深色夹料的方形饼干，与 021 的浅色松脆饼干形成同族差异。

## 生成与替换流程

1. 建立逐项提示词清单，记录资源 ID、语义参考、必须出现的结构和禁用元素。
2. 通过 `chordvers-imagegen` 的 `gpt-image-2` 路径逐项生成纯色键背景母稿，并保存到 `output/imagegen/item-redraw/sources`。
3. 本地去背后保存到 `output/imagegen/item-redraw/clean`，再以最近邻缩至 16×16 候选目录。
4. 生成候选联系表，在原尺寸和 8 倍放大尺寸下检查：主体是否一眼可辨、是否仍像广告、是否出现文字/品牌、是否与相邻物品混淆。
5. 只将通过检查的候选复制到正式资源目录；同步 `tools/generate_original_textures.py`，保证生成器能逐字节复现正式 PNG。
6. 更新资源清单、原创替换记录、实施记录与 `AGENTS.md` 索引。

## 失败处理

- 若母稿仍呈现包装广告、场景或人物，废弃该版本并只修改一个主要变量重新生成。
- 若去背出现绿色边缘或主体误删，重新选择键色或收紧主体色约束，不把带毛边结果进入正式资源。
- 若 16×16 下无法识别，减少部件和颜色，而不是提高输出分辨率或加入文字。
- 若资源路径、模型引用或注册引用发生变化，视为失败并恢复到原引用。

## 验收标准

1. 59 张正式物品 PNG 全部仍为 16×16 RGBA，并通过透明度、边界和文件解码检查。
2. 正式物品贴图不含广告背景、品牌、包装文字、人物摄影或可读文案；联系表逐项人工检查通过。
3. 001 的用户现有未提交成果没有被批量过程覆盖。
4. `models/item`、Java 注册与功能代码相对任务开始时无非预期改动，所有纹理引用都能解析。
5. 生成器复现检查、资源清单 SHA-256 检查和项目质量契约通过。
6. 文档明确记录参考素材当前不可访问，不虚构逐图参考证据。
