# P1 全量运行验收矩阵

> 目标：把 P1 从“可构建、专服可启动”提升为真实客户端、双客户端并发和生命周期恢复均有机器断言。动态 Forge/Gradle/Minecraft 测试只允许在 GitHub Hosted Runner 执行。

## 必需工作流

1. `single-client.yml`：Xvfb + Mesa 启动真实 Forge 1.20.1 Client，进入主菜单并连接本次 Jar 的专服；正常退出，客户端与服务端无 crash-report、FATAL、Mixin/客户端类泄漏。
2. `multi-client.yml`：两个独立游戏目录、独立玩家身份的真实客户端连接同一专服，执行 P1 业务探针。
3. `lifecycle-recovery.yml`：固定测试世界与玩家 UUID，执行 `save-all flush` 后 SIGKILL(-9)，用同世界重启并核对资产与事务状态。
4. `regression-report.yml` 或汇总 Job：任何必需 Job failed/skipped/missing 均失败；上传机器可读结果、完整日志、crash-report（若有）、产品 Jar 与 SHA-256。

## P1 业务断言

|场景|前置与操作|必须断言|
|---|---|---|
|空奖池开盒|玩家持有唯一 token 的盲盒，奖池为空，长按完成|盲盒不消耗；库存不变；奖池仍为 0；服务端存活|
|正常打包|选择多个不同槽位、不同数量且带唯一名称/NBT 的物品|精确扣除；只增加 1 个完整 bundle；只交付 1 个唯一 token 盲盒；总资产守恒|
|伪造打包包|错误容器 ID、越界槽位、重复槽位、过量数量、过期指纹、禁打包物、关闭菜单后提交|全部拒绝；库存/奖池不变；无断线和服务端异常|
|菜单关闭|打开打包菜单后关闭，不提交|无物品临时转移；库存与奖池不变|
|满背包打包|没有空间接收盲盒|事务不开始或完整回滚；被选物品不扣；奖池不增加|
|正常开盒|奖池含唯一 bundle，背包可容纳|恰好消耗 1 个 token；恰好删除被选 bundle；完整 NBT 奖品只交付一次|
|满背包开盒|bundle 无法完整容纳|盲盒不消耗；奖池条目不删除；无地面公共掉落；资产守恒|
|中止开盒|长按期间松手、换手、死亡、掉线|不开盒；不消耗 token；减速修饰器清理；重连后无残留使用态|
|两人竞争一条奖池|两个客户端近同时完成开盒，奖池仅 1 条|最多 1 人成功；另一人保留盲盒；bundle 只交付一次；奖池为 0|
|并发打包|两个客户端分别打包唯一 NBT 资产|产生 2 条不同 UUID bundle 和 2 个不同 token；不串玩家、不覆盖版本|
|断线重连|PREPARED/COMMITTED 边界附近断线并重连|不会重复扣除/补发；事务只归属原玩家；状态可审计|
|正常保存重启|打包和开盒后 `save-all flush`、正常 stop、重启|奖池、事务、玩家库存与 token UUID 保持一致|
|强杀恢复|在预设阶段写 marker，`save-all flush` 后 SIGKILL(-9)，同世界/同 UUID 重启|逐槽物品、奖池条目、事务阶段、token 与 payload 总量可核对；无复制/吞失；需要隔离时必须稳定进入 `MANUAL_REVIEW` 且 payload 完整|
|错误方向/突发包|发送错误方向、未知容器、无权限命令、有限突发请求|服务端拒绝且存活；无越权、无状态变化、无包洪水失控|

## 资产守恒口径

测试资产必须含唯一名称、耐久、附魔和自定义 NBT。每个检查点生成 canonical JSON：玩家逐槽物品、光标栈、奖池 bundle、事务 payload、地面归属掉落、token UUID。按物品 ID + 数量 + 规范化 NBT 汇总，事务隔离中的 payload 计入“受控资产”，但同一资产不得同时出现在玩家库存和可领取奖池中。

## 禁止伪通过

- 不得用纯单元测试、编译成功、客户端日志启动前半段或伪造 marker 代替真实 Forge Client/Server。

- 测试探针只能注入 CI 临时产物，不得进入正式发布 Jar。
- 未执行的掉电窗口必须列为未覆盖，不得从 `save-all flush` 后强杀结果外推。
