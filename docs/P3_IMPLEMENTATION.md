## 已锁定的实施边界

### 服务端权威与持久状态

* 只新增一个挂在玩家身上的 Capability。易筋经的已学习状态和二段跳个人冷却到期刻写入其 NBT；本次滞空的二段跳使用标记只由服务端运行期维护并在落地重置，不在 Capability 中保存玩家、世界或实体的强引用。
* 首次学习、物品消耗、固定 UUID 的最大生命与攻击属性对账、空中跳次数和速度均由逻辑服务端决定。重复使用不得重复叠加属性或重复消耗物品。真实客户端专项先在临时平台上收到服务端能力同步，再释放为带干草安全着陆的受限腾空并由真实 `KeyMapping` 发送 C2S，不能以到达/落地竞争、摔死或反飞行断线伪造按键成功或失败。
* 玩家死亡克隆、登录、换维、开始被跟踪和状态变更后均须同步。客户端仅缓存已同步的能力数据并处理按键/显示，不能自行授予能力、计算冷却或施加速度。009 的专项 ciTest 已静态接入真实 `KeyMapping` 点击、`StartTracking`、原版死亡 Clone、跨维以及 `save-all flush → SIGKILL → 同目录重启`；必须等待 Hosted Runner 动态结论，不得以现有第一批绿灯外推。
* 二段跳只能由受方向限制的 C2S 意图包请求。服务端须重新核验玩家存活、非睡眠、已学习、非旁观、非原版飞行、腾空状态、一次腾空尚未使用及冷却，再施加默认初速度 `0.42` 和保守的 5 tick 个人冷却；落地状态只由服务端重置。

### 交互、实体与物品守恒

* 011 的猪扫描、范围判定、冷却、扫描上限和繁殖触发全部在逻辑服务端执行。默认范围为以使用者为中心的 10 格球形；冷却和扫描上限以服务器配置为准，不能让客户端提供目标列表。
* 008、016 共用抱枕投掷实体与座位实体，物品放置、上座、下座、蓄力、实体生成、命中伤害与回收均由服务端处理。两种抱枕以受同步的变体数据区分，不能在客户端生成实体或以客户端标记决定命中。投掷实体保存完整单件 `ItemStack`、变体、返还标记、命中标记、目标 UUID 与回收延迟；命中后无物理保留 4 个服务端 tick 供客户端真实观察，再以成功生成的掉落物为前提回收，缺失完整栈时保留实体并记录错误，绝不以默认变体静默替换。
* 抱枕座位只允许一名乘客；方块拆除即时清理。玩家断线、死亡或换维时服务端生命周期事件会主动下座并销毁其抱枕座位，而不是只依赖后续 tick 的被动空座检查。
* 045 以原版三叉戟的服务端投掷/返航语义为基线。投出的完整 `ItemStack`、主人 UUID、返航态、命中目标 UUID 和飞行计数写入实体 NBT；主人 UUID 同步仅供客户端真实观察。生存模式只在实体成功加入世界后扣原栈，回收时优先入原主人背包，满包才在主人位置生成掉落物且确认加入成功后销毁实体；主人离线、死亡、换维、旁观或掉落实体加入失败时保留实体，不能静默吞物。创造模式不返还以避免复制；普通拾取被禁用。投掷伤害保留三叉戟基线及投出栈附魔加成。虚空返航仅在低于原版虚空高度阈值时触发，普通空中飞行绝不因生命周期钩子提前返航。
* 033 保持铁头盔等值的耐久和护甲语义。P3 交付最低可运行盔甲层；专属路障模型与精细动画仍留 P5，不能提前宣称完成。

### 双端隔离与资源

* 公共生产代码和专服加载路径不得导入客户端类。按键、客户端能力缓存、座位/飞行显示和模型渲染放入客户端隔离入口；C2S/S2C 包各自显式声明方向。
* P3 新增的图标、方块、实体、盔甲层、模型和双语文本均须可运行且为原创资源。不得添加原始照片、压缩素材、第三方成品贴图或在线音频文件。
* P3 开始引入 S2C 后，质量门禁必须按包逐一断言方向：打包与二段跳是 C2S，能力同步是 S2C；不得保留“全局禁止 S2C”的过时断言。

## 验收方式与真实未覆盖边界

隔离探针只能存在于 `src/ciTest` 及独立 ciTest Jar，正式 Jar 不得含 `cn/blindboxchallenge/citest/`。探针必须从真实服务端状态读取断言，客户端观察标记只能在真实观察到坐姿、投掷实体和返航之后产生；禁止预写标记、`continue-on-error`、删除失败场景或用编译成功代替行为覆盖。两客户端探针还必须保留 P1 canonical 资产守恒和 P2 已有业务回归。

当前 P3 为 **6/6 静态实现、3/6 批次已验证、0/6 阶段验收**。第一批隔离探针从真实专服状态断言首次/重复学习、属性 UUID、未学习拒绝、一次腾空限制、落地重置、5 tick 个人冷却、服务端速度及铁头盔等值属性；现有真实双客户端断线重连夹具还会在断开前学习、重连后复核 Capability NBT 和固定 UUID 属性，再清理 P3 状态。第二批已在真实服务端书本入口断言 10 格球形过滤、引擎级候选硬上限、成对繁殖、书本保留与服务端冷却；新增客户端专项让两名真实客户端各自观察同一对父猪及由真实书本入口产生的幼猪，再由服务端逐 UUID 回查。第三批探针已通过真实 `BlockItem#useOn`、抱枕长按入口和服务端状态验证放置、单座、拆除清理、两种满蓄力投掷、石抱枕命中、钻石抱枕超时及带 NBT 的两种物品守恒；两个真实客户端在观察到同一座位、两个投掷实体、石抱枕命中目标 UUID 与两枚回收掉落物后写 marker，服务端逐项核对 UUID，已随第三批六门禁成功。第四批返航剪刀探针经真实 `use/releaseUsing` 投掷两次：第一次立即对远距离真实目标执行生产 `AbstractArrow` 扫掠，要求两客户端从同一同步投掷实体读到投掷/目标/主人 UUID 和返航态；不得冻结投掷实体伪造客户端观察窗口或消耗生产飞行预算。第二次在 36 格背包均满时只接受主人位置的一件完整 NBT 兜底掉落物；该探针与 011 专项都尚待 Hosted Runner。009 的真实客户端按键/C2S、死亡 Clone、换维、跟踪与强杀恢复专项同样尚待当前 Hosted Runner 结论。P1 已知的“未执行 `save-all flush` 的真实掉电窗口”仍未覆盖，不能外推为已解决；其余 P4/P5 范围同样不属于 P3 结论。完整门禁状态与后续真实运行编号见 [P3 验收矩阵](P3_ACCEPTANCE.md)。
